# Porting ledger (web app)

What moved from the original app into this repo, and what changed on the way. The backend half is tracked in the platform repo's `docs/porting-ledger.md`.

**Source:** the Lovable-connected Spatial Capture repo, branch `develop`, commit `12ad87b`, **including its uncommitted changes**: three decay chirps per auto-scan viewpoint in `src/routes/capture.tsx`, `combineViewpointProbes` in `src/lib/acoustics.ts`, and the new `src/lib/acoustics.test.ts`. The source repo itself was not changed.

## Phase 4 — ported

### Routes

| Source (`src/routes/`) | Changes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `__root.tsx`           | No HTML shell (`index.html` carries it), no `Scripts`, no Lovable error reporting. The CSP meta tag moved to the build and the hosting config. Adds `AuthProvider`                                                                                                                                                                                                                                                                                                                                                                                                                |
| `auth.tsx`             | `api.signIn` / `api.signUp` instead of Supabase Auth. **"Continue with Google" removed**: the in-house auth has no Google sign-in yet (decision D13). Adds a "Forgot your password?" link                                                                                                                                                                                                                                                                                                                                                                                         |
| —                      | New: `auth_.verify-email.tsx` and `auth_.reset-password.tsx`, the pages the API's emails link to                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `index.tsx`            | One cursor-paginated query with search, status filter and sort on the server (was: all rows, filtered in the browser), thumbnails in the response (was: a second signed-URL query), totals from the API, "Show more". The fire-and-forget `sweepStalledScans` call is gone: the worker sweeps stalled runs                                                                                                                                                                                                                                                                        |
| `space.$id.tsx`        | One `GET /v1/scans/:id` (was: five reads plus a signed URL per frame). Analysis: `POST` queues the run and the page follows it over SSE; the "leave during reconstruction?" guard is gone because leaving no longer interrupts the run. Privacy sweep: queued as a job, the result is reported when it lands                                                                                                                                                                                                                                                                      |
| `capture.tsx`          | `POST /v1/scans` (idempotent per capture id), frames and the depth file straight to Blob Storage (`uploadToScan`), then `runAnalysis`. A retried submit whose frames already landed doesn't upload them twice. On an analysis failure the page no longer writes `status = failed` itself: the server does. Reshoot: one upload with `replaceStations`, so the server saves the new frames and removes the old viewpoints' frames in one transaction (was: upload, insert rows, then delete, from the browser); notes are merged with `PATCH`. Consent and address through the API |

A route is done when it has no `supabase` import (plan §13.2): none remains, and ESLint rejects `@supabase/*` and `@tanstack/react-start` imports.

## Known gaps

- **Uploads don't resume across a reload.** The capture draft in IndexedDB keeps the wizard's progress but not the frames themselves (by design in the original), so a reload mid-upload means capturing again. Retries within a session are handled.
- The capture wizard itself (camera, compass, motion, microphone) needs a phone; the end-to-end test drives the same API calls the capture page makes, not the wizard UI.
